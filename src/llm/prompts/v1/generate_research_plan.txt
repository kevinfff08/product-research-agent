You are a research planning expert. Given the decomposition of a product idea into research paths, generate a structured research plan with specific search queries for each data source.

## Original Input
{original_input}

## Decomposition
{decomposition_json}

## Research Weights
- Industry research: {weight_industry}
- Academic research: {weight_academic}
- Community research: {weight_community}

## Instructions
For each research path, generate specific, targeted search queries for each source:
- **tavily**: Web search queries for products, companies, blog posts, documentation
- **academic_web**: Academic web search queries for papers, benchmarks, proceedings, model cards, and Papers with Code pages
- **code_web**: Web search queries for open-source implementations across GitHub, GitLab, Hugging Face, Sourcegraph-indexed repos, and official docs
- **arxiv**: Preprint search queries (use field-specific terms)

Prioritize queries based on the research weights. More queries for industry sources.
Use varied intents so the execution layer can fan out search:
- product_landscape: products, competitors, pricing, official docs
- alternatives: comparisons, "best X", "X vs Y", adoption notes
- repo_discovery: open-source implementations and maintained libraries
- evidence: benchmarks, evaluations, surveys, failure modes
- community: user complaints, issues, HN/Reddit/Product Hunt discussions

Avoid near-duplicate queries. Prefer concrete nouns and domain terms over generic prompts.

## Output Format
Return a JSON object:
{{
    "search_queries": [
        {{
            "query": "specific search query",
            "source": "tavily|academic_web|code_web|arxiv",
            "path_id": "p1",
            "priority": 0.9,
            "intent": "product_landscape|alternatives|repo_discovery|evidence|community"
        }}
    ],
